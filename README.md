#  Анализ продаж сети кофеен — Power BI Project 

## Задача проекта

Построить дашборд «Анализ продаж розничной сети» за январь–июнь 2025 г.:

- **Выручка** и количество проданных товаров;
- **Динамика выручки по месяцам** и рост к прошлому месяцу;
- **ТОП товаров** по выручке с разбивкой по категориям;
- **Сравнение магазинов** («Центр», «Север», «Юг»);
- **Кумулятивная выручка** с начала года;
- **Средняя цена** как показатель структуры продаж.

Данные — учебные (144 записи), сгенерированы прямо внутри модели на Power Query (M),
поэтому проект открывается сразу с данными, без внешних файлов.

## Как открыть

1. **Требование:** последняя версия Power BI Desktop (PBIP GA начиная с 2025 года).
2. Включите режим разработчика: `Файл → Параметры и настройки → Параметры →
   Глобальные → Возможности предварительной оценки` → включите
   **«Режим разработчика» (Developer Mode)** и **«Сохранение в формате Power BI
   Project (.pbip)»**, перезапустите Desktop.
3. Соберите файлы по структуре выше (важно: имена папок с точкой —
   `SalesAnalysis.Report` и `SalesAnalysis.SemanticModel`).
4. Двойной клик по **SalesAnalysis.pbip**. Откроется «толстый» проект:
   отчёт + модель редактируются вместе.

Если Desktop пожалуется на отчёт (PBIR формат свежий) — запасной путь:
откройте напрямую `SalesAnalysis.SemanticModel/definition.pbism`, проверьте данные
и меру, а отчёт соберите заново через `Создать` → визуализации из этой модели.

## Модель данных

**Связи** (все «один ко многим», фильтрация от справочника к факту):

| Из | В | Тип |
|---|---|---|
| Товары.ID_товара | Продажи.ID_товара | 1 : * |
| Магазины.ID_магазина | Продажи.ID_магазина | 1 : * |
| Календарь.Дата | Продажи.Дата | 1 : * |

**Меры** (в таблице «Продажи»):

```
Количество продано       = SUM(Продажи[Количество])
Выручка                  = SUMX(Продажи, Продажи[Количество] * Продажи[Цена])
Средняя цена             = DIVIDE([Выручка], SUM(Продажи[Количество]))
Выручка за прошлый месяц = CALCULATE([Выручка], DATEADD('Календарь'[Дата], -1, MONTH))
Рост к прошлому месяцу % = DIVIDE([Выручка] - [Выручка за прошлый месяц],
                                 [Выручка за прошлый месяц])
Кумулятивная выручка     = CALCULATE([Выручка], DATESYTD('Календарь'[Дата]))
```

Таблица «Календарь» — вычисляемая (`CALENDAR` на весь 2025 год), чтобы
time-функции DAX работали корректно на любой период.

## Как построить дашборд (рекомендуемый макет)

**Страница «Обзор»**
1. Карточка: мера `Выручка` (слева сверху).
2. Карточка: мера `Рост к прошлому месяцу %`.
3. График (столбчатый с линией): ось `Календарь[Год-Месяц]`, столбцы `Выручка`,
   линия `Кумулятивная выручка`.
4. Кольцевая диаграмма: легенда `Магазины[Название]`, значения `Выручка`.

**Страница «Товары»**
1. Гистограмма: ось `Товары[Название]`, значения `Выручка` — отсортировать по убыванию.
2. Таблица: `Товары[Категория]`, `Товары[Название]`, `Количество продано`, `Выручка`.

**Страница «Магазины»**
1. Столбчатая диаграмма: ось `Магазины[Название]`, значения `Выручка`.
2. Линейный график по месяцам с легендой `Магазины[Название]`.
3. Срез (slicer) по `Календарь[Год-Месяц]`.

## Глоссарий

- **PBIP** — формат проекта Power BI: точка входа `.pbip` указывает на папку отчёта.
- **TMDL** — человекочитаемый язык описания семантической модели (YAML-подобный).
- **PBIR** — новый формат отчёта: каждая страница и визуализация — отдельный JSON.
- **definition.pbir** — «клей»: свяжет отчёт с моделью (`byPath` — толстый отчёт).

## Идеи развития

- Срезы по категориям и периодам, закладки (bookmarks) для переключения месяцев.
- Мера `Ср. чек = DIVIDE([Выручка], DISTINCTCOUNT(Продажи[Дата]))` при данных на уровне чеков.
- Параметры What-If для планирования выручки.
- Публикация в Power BI Service и обновление по расписанию.
